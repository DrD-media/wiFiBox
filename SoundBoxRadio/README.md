# SoundBoxRadio

Локальное радио: музыка и микрофон компьютера → ESP32 → PCM5102A → PAM8403.
Проект находится в `C:\Work\WiFi_SoundBox\SoundBoxRadio`.

## Запуск без интернета

1. Дважды нажмите **START_RADIO.cmd** в корне проекта.
2. Откроется пульт `http://127.0.0.1:5000/`. Оставьте окно сервера открытым.
3. Выберите трек или плейлист. Для голоса выберите устройство записи и нажмите «Включить микрофон».
4. «Музыка», «Микрофон» и «Эфир» имеют отдельные громкости 0–100 и кнопки отключения звука.
5. Красная кнопка «Снять всё с эфира» останавливает музыку и захват микрофона.

Музыка и микрофон смешиваются постоянно; переключателя режимов больше нет. Микрофон подключается к **компьютеру сервера**, а не к ESP32. Разрешите доступ к нему в настройках Windows. Для проверки голоса пользуйтесь наушниками, чтобы избежать акустической обратной связи.

Python, Flask, PyAudio, FFmpeg, Node.js и зависимости интерфейса находятся **внутри проекта сервера**. PlatformIO, компилятор, Arduino и собственный Python находятся в соседнем самостоятельном проекте **SoundBoxFirmware** (бывшая Temper1). Запуск ничего не скачивает и не устанавливает. Системные Python, Node.js и npm не нужны. Для работы нужна локальная сеть Wi-Fi; подключение к интернету не требуется. Переносите папку проекта целиком, включая `runtime`, `frontend/dist` для сервера. Папку `../SoundBoxFirmware` переносите целиком отдельно. Установленный в Windows браузер и драйвер USB платы относятся к операционной системе.

## Обязательно обновите ESP32

Старые сервер и прошивка несовместимы с новым потоком. Прошивка — отдельный проект **`C:\Work\WiFi_SoundBox\SoundBoxFirmware`**, бывшая папка Temper1. Единственный исходник — `../SoundBoxFirmware/src/main.cpp`, готовые образы — `../SoundBoxFirmware/dist`.

1. Подключите ESP32 кабелем USB с передачей данных.
2. Запустите `../SoundBoxFirmware/FLASH_ESP32.cmd` и выберите номер USB устройства ESP32. Или передайте порт: `..\SoundBoxFirmware\FLASH_ESP32.cmd COM5`.
3. Если плата ожидает подключение загрузчика, удерживайте BOOT в начале прошивки. Монитор последовательного порта должен быть закрыт.
4. После загрузки подключитесь к Wi-Fi **SoundBoxRadio-Setup**, откройте **http://192.168.4.1**, задайте свою сеть Wi-Fi, IPv4 компьютера и порт **5000**.
5. Адреса компьютера видны в разделе пульта «Подключение». Компьютер и ESP32 должны находиться в одной локальной сети. В Windows разрешите входящий TCP 5000 для частной сети.

Полный образ `SoundBoxRadio-full.bin` записывается с адреса **0x0**. `SoundBoxRadio-app.bin` — только приложение для адреса **0x10000**, без загрузчика. Полный образ не стирает всю flash, прежние настройки Wi-Fi сохраняются, если раздел NVS совместим.

GPIO13: короткое нажатие переключает тишину; удержание 3 секунды перезапускает плату в режиме настройки. GPIO14: горит при воспроизведении, мигает при ожидании. Веб-страница приёмника также доступна по его IPv4 в рабочей сети: там находятся громкость, тишина, состояние буфера и счётчики сбоев сети.

## Подключение вашей платы

| ESP32 | PCM5102A / элемент |
| --- | --- |
| GPIO25 | LCK / LRCK |
| GPIO26 | DIN |
| GPIO27 | BCK |
| GPIO13 | кнопка → GND |
| GPIO14 | LED через 330 Ом → GND |

PCM5102A: FMT, FLT, DEMP, SCK → GND; XSMT → 3.3 V. Питание модулей — по вашей схеме от 5 V с общей землёй. Выходы R/G/L ЦАП идут на входы R/G/L усилителя. Динамик подключён между R+ и R− PAM8403; выводы динамика не соединяются с землёй.

Прошивка объединяет левый и правый каналы и подаёт моносигнал на оба выхода ЦАП: единственный динамик получает всю музыку. Ограничение цифрового уровня перед ЦАП задано коэффициентом **0.08 (около −22 дБ)**. Это консервативный предел для PAM8403: у [PCM5102A выход до 2.1 Vrms](https://www.ti.com/lit/ds/symlink/pcm5102a.pdf), а у [PAM8403 усиление 24 дБ](https://www.diodes.com/part/view/PAM8403/). Перегрузка аналогового входа была вероятной дополнительной причиной хрипа; без измерений на плате это предположение. При 100% в пульте этот аппаратный предел сохраняется.

Если хрип остаётся на низком уровне после обновления обоих компонентов, проверьте просадку питания 5 V, общую землю, динамик и соединения. Программное ограничение не устраняет неисправность питания или усилителя.

## Как устроен поток

Один сервер отдаёт интерфейс, API и звук на порту 5000. Один аудиопоток: **48 000 Гц, PCM signed 16-bit little-endian, stereo**, кадры по **20 мс / 3840 байт**.

- `/api/radio/stream` — чистый PCM для ESP32, без HTTP chunk-разделителей.
- `/api/radio/stream.wav` — тот же эфир с WAV-заголовком для браузера.
- `/api/radio/status` — источники, громкости, пиковые уровни, лимитер и ошибки.
- `/api/radio/levels` — независимые уровни и отключение источников.

Декодирование FFmpeg и захват микрофона отделены от равномерной отправки. Микрофон 44.1 кГц преобразуется в 48 кГц с сохранением состояния; удаляются постоянная составляющая и низкочастотный гул. Общий стереолимитер предотвращает цифровую перегрузку суммы голоса и музыки. Каждый слушатель имеет ограниченную очередь; отставший клиент не блокирует остальных.

На ESP32 сеть и I2S обслуживаются разными задачами. TCP собирается в полные PCM кадры независимо от границ пакетов. Стартовый запас — 120 мс, очередь — до 240 мс плюс DMA. При нехватке данных приёмник плавно уходит в тишину и заново заполняет буфер; при разрыве переподключается. Фактическую общую задержку на физическом ESP32 пока не измеряли. Кнопка тишины в пульте очищает серверные очереди, но ранее отправленные данные ещё могут доиграть из буфера приёмника. Кнопка GPIO13 глушит звук локально.

## Папки

| Папка | Содержимое |
| --- | --- |
| `backend` | сервер, звуковой движок, каталоги JSON и медиафайлы |
| `frontend` | исходники пульта, локальные зависимости и готовый `dist` |
| `../SoundBoxFirmware` | отдельный проект ESP32: исходники, библиотеки, компилятор и образы `dist` |
| `runtime/python` | автономный Python 3.11 и библиотеки в `vendor` |
| `runtime/node` | Node.js для пересборки интерфейса |
| `../SoundBoxFirmware/runtime/platformio` | локальные средства сборки ESP32 и Arduino |
| `tools` | сборка, прошивка и проверка автономного запуска |
| `docs` | описание изменений и результаты проверок |
| `logs` | журнал сервера с ротацией и журнал автономной проверки |

Старая `.venv` больше не используется; её удаление отклонила автоматическая проверка среды. При переносе проекта она не нужна.

## Разработка и проверка без интернета

- `tools\build_web.cmd` — собрать интерфейс локальным Node.js; обычному запуску пересборка не требуется.
- `..\SoundBoxFirmware\BUILD_FIRMWARE.cmd` — собрать прошивку локальным компилятором и обновить оба образа. Старый `tools\build_firmware.cmd` перенаправляет туда же.
- `..\SoundBoxFirmware\LIST_PORTS.cmd` — показать доступные последовательные порты.
- `runtime\python\python.exe -I -m unittest discover -s backend -p "test_*.py" -v` — тесты движка и API.
- `runtime\python\python.exe -I tools\verify_offline.py --microphone --seconds 60` — запустить настоящий сервер с пустым PATH и запретом внешних соединений, проверить два потока и микрофон. Перед этим закройте обычный сервер. Проверка включает микрофон, читает поток в память, не сохраняет запись и не изменяет каталог.

Результаты последнего успешного прогона: `docs/validation.json`. Подробности и оставшиеся аппаратные проверки: `docs/CHANGES.md`. Журнал ошибок: `logs/server.log`.
